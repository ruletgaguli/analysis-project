# analysis-project

## Проектная работа модуля 6. Рефакторинг кода на Rust

Рефакторинг учебного анализатора логов: разбор записей `System` и `App`, фильтрация по идентификаторам запросов, ошибкам и операциям обмена. Формат входа, исходные тест-кейсы и вывод CLI на `example.log` сохранены. Незавершённая предметная логика прототипа не дописывалась.

## Сборка и запуск

```bash
cargo build --locked
cargo run --locked -- example.log
```

CLI печатает демонстрационный разбор объявлений, имя открываемого файла и все разобранные записи. Отсутствие аргумента, недоступный файл или некорректный лог завершают программу с ненулевым кодом и сообщением в stderr, без паники.

Учебный формат не является JSON: у полей и элементов списка обязательны завершающие запятые, имена структур входят в запись. `example.log` оставлен без изменений.

## Изменения по ТЗ

Все 13 мест, отмеченных в исходнике подсказками, исправлены. Для каждого из 11 видов проблем устранены все отмеченные случаи, что превышает обязательные 80%.

| Требование | Реализация | Проверка |
|---|---|---|
| Убрать лишние `clone()` | Парсеры принимают `&str`, остаток и повторные попытки разбора используют ссылки | `remainder_borrows_original_input`, исходные тесты |
| Убрать избыточный `Rc<RefCell<T>>` | `read_log` принимает источник по значению или через `&mut R` | `supports_owned_and_borrowed_readers_without_static_lifetime` |
| Заменить циклы итераторами | Чтение: `lines`, `enumerate`, `filter_map`, `collect`; поиск ID: `contains`; повторный разбор: `try_fold` | Проверки фильтров и комбинаторов |
| Убрать ненужный `unsafe` | Удалены `transmute`, искусственный `'static` и обёртка `RefMutWrapper`; в библиотеке и CLI стоит `forbid(unsafe_code)` | Сборка, тесты, Miri |
| Убрать singleton | Нет `LOG_LINE_PARSER` и `OnceLock`, парсеры создаются локально | Исходный `test_all`, общий API разбора |
| Использовать tight-типы | `NonZeroU32` хранится в количествах, капитале, ликвидности и request ID; `NonZeroI32` для знакового разбора | `nonzero_numbers_preserve_invariants` |
| Заменить дублирование дженериками | Шесть однотипных функций заменены на `just_parse<T: Parsable>` | `generic_parser_supports_different_types` |
| Заменить лишние трейт-объекты | `read_log<R: Read>` вместо `Box<dyn MyReader>` | Срез, `Cursor`, файл, тестовый источник |
| Заменить цепочки `if` на `match` | `ReadMode::{All, Errors, Exchanges}`, исчерпывающая обработка режимов | `filters_preserve_order_and_original_exchange_selection` |
| Уменьшить большой вариант enum | `AuthData` содержит `Box<[u8; 1024]>`, массив сразу создаётся из буфера в куче | Проверки данных, длины и размеров типов |
| Возвращать ошибку вместо паники | `ParseError`, `ReadLogError`, `Result` в API; ошибочный режим исключён типом | Ошибки I/O, разбора и аргументов CLI |

В парсерах строк и списков оставлены циклы, где нужно последовательно вести состояние и завершать разбор на разделителе. Это не отмеченные в ТЗ циклы фильтрации. Ленивые альтернативы парсеров также не заменяются на eagerly вычисляемые ветви.

`Box<dyn Error>` в CLI объединяет разные типы ошибок на границе приложения, а `Error::source` следует стандартному контракту ошибок. Это не динамический выбор источника чтения и не замена дженериков трейт-объектами.

## API и контракты

```rust
use analysis::{ReadMode, read_log};
use analysis::parse::{Backet, just_parse};
use std::num::NonZeroU32;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let source = b"System::Error NetworkError \"no network\" requestid=1\n";
    let ids = [NonZeroU32::new(1).unwrap()];
    let errors = read_log(source.as_slice(), ReadMode::Errors, &ids)?;
    assert_eq!(errors.len(), 1);

    let (remaining, backet) = just_parse::<Backet>(
        r#"Backet{"asset_id":"milk","count":3,}tail"#,
    )?;
    assert_eq!(remaining, "tail");
    assert_eq!(backet.count.get(), 3);
    Ok(())
}
```

`just_parse` разбирает префикс и возвращает заимствованный остаток. Поля с текстом владеют своими строками, поэтому запись не зависит от буфера чтения. Числа проверяются при разборе и дальше хранятся как `NonZero`, не позволяя записать ноль в структуру.

`read_log` пропускает пустые строки, сохраняет порядок записей и применяет оба фильтра. Пустой список ID отключает фильтрацию по ID. Каждая непустая строка должна разбираться целиком. Ошибка возвращает номер строки и источник; в отличие от прототипа, ошибочное чтение не выдаётся за успешный частичный результат. Проверяется весь вход, включая записи, которые потом не проходят фильтр.

Состав режима `Exchanges` сохранён: создание пользователя, регистрация актива, внесение/вывод денег, покупка и продажа. Удаление пользователя и снятие регистрации актива в него не входят.

Исторические имена `Backet` и полей сохранены. В исходном прототипе `WithdrawCash` разбирался как `DepositCash`: это поведение предметной логики оставлено вне данного рефакторинга и закреплено тестом, чтобы не скрывать изменение поведения под изменением структуры кода.

## Проверки

```bash
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
cargo test --locked --doc
cargo test test_all -- --nocapture
cargo run --locked -- example.log
```

Исходные 16 тестов сохранены, ожидания адаптированы к ссылкам, `NonZero` и `Box`. Добавлены 3 теста комбинаторов, 10 регрессионных и 4 проверки CLI: всего 33 теста плюс пример документации. `tests/fixtures/example.stdout` содержит вывод исходного CLI, записанный до изменений; только абсолютный путь рабочего каталога заменён на `{cwd}`. Тест сравнивает весь вывод, включая байты авторизации.

Проверки памяти для библиотеки и регрессионных тестов:

```bash
rustup component add --toolchain nightly miri
cargo +nightly miri test --locked --lib --test regression
```

CLI-тесты запускают отдельный процесс и выполняются обычным `cargo test`.

Локально прошли сборка, форматирование, Clippy с запретом предупреждений, все 33 теста и пример документации. Miri успешно проверил 19 тестов библиотеки и 10 регрессионных тестов. Вывод CLI на `example.log` побайтово совпал с выводом до рефакторинга.
